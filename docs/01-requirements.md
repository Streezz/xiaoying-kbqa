# 01 需求：用户、目标、范围和成功标准

## 用户

公司员工。他们问的是制度问题（报销、年假、加班、设备）和产品问题（星剪会员的登录、退款、发票）。
他们的问法很口语，常常不完整，会接着上一句追问，也会带着错误的听说来问。

## 目标

给员工一个能放心照着做的答案：

- 答案有原文出处，员工能点开核对。
- 资料说法不一致时，告诉员工哪里不一致、要确认什么，而不是替他挑一个。
- 资料里没有的，明确说没有，并说缺什么。
- 查不到、工具坏了、步数用完时，返回明确的状态，不把"没做完"说成"做完了"。

## 范围

做：

- CLI 问答，单轮和多轮（同一个 `--session` 算一段对话）。
- 3 个查资料工具：检索、读原文、查文档信息；1 个提交工具。
- 合成资料 11 份 + 4 套变体（`data/`）。
- 证据账本、原文校验和独立回答依据检查。
- 检索分页、用户确认审计与导出。
- 故障注入、步数和工具调用上限、录制回放、离线 Mock。

不做：

- 向量检索、Web 界面、HTTP API、多 Agent、线上部署。
- 权限控制（谁能看哪份制度）。
- 把用户的确认写回知识库。

## 输入和输出

输入：问题，可选的会话 ID（带上就有对话历史）。

输出（JSON 字段，CLI 默认打印成文字，`--json` 打印原样）：

| 字段 | 含义 |
|---|---|
| status | ANSWERED / NEED_CONFIRMATION / NEED_CLARIFICATION / NO_EVIDENCE / FAILED / INCOMPLETE |
| answer | 给员工看的回答 |
| citations | 引用：文档 ID、段落、标题、版本日期、状态、原文整句 |
| conflicts | 冲突：主题、各方说法、查证情况、resolution（未解决/本轮用户确认） |
| grounding | 回答依据检查结果；Mock 明确标记为 mock_review |
| confirmation | 本轮用户明确选定冲突文档时的原话、轮次、版本和哈希 |
| gaps | 资料缺口 |
| clarify_question | 需要用户确认或补充的问题 |
| doc_verdicts | 本轮读过的每份文档的表态：依据 / 冲突 / 不适用 |
| steps_used / tool_calls / gate_rejections | 模型调用次数、工具调用次数、核验退回次数 |

状态怎么选：

| 状态 | 什么时候 |
|---|---|
| ANSWERED | 有原文支持的答案，可以带 gaps（部分子问题没查到） |
| NEED_CONFIRMATION | 资料冲突，且版本、生效日期、适用范围都判断不了谁优先 |
| NEED_CLARIFICATION | 问题太模糊，不知道问的是什么 |
| NO_EVIDENCE | 资料里没有 |
| FAILED | 工具失败，换路后仍拿不到原文；或模型调用失败 |
| INCOMPLETE | 模型或工具调用额度耗尽，还没有通过核验的结果 |

## 成功标准

题目 6 个必须验收点与扩展业务场景均有用例和真实模型运行记录，实际通过情况见 03：

| 验收点 | 用例 |
|---|---|
| 明确答案 | C01、C05、C12、C15、C18 |
| 文档冲突 | C02、C04、C08、C10、C11、C13、C14、C16 |
| 资料外问题 | C03、C15、C19 |
| 改写后的相似问题 | C04（和 C02 同义，结论应一致） |
| 上下文追问 | C05、C10、C11、C18、C20 |
| 工具失败 | C06（换路成功）、C07（无法完成）、C08（冲突一方读不到） |
| 步数上限 | C09 |
| 替换文档后答案和动作变化 | C12、C13、C16、C20 |
| 问题模糊需要追问 | C17 |

用例文件在 `examples/cases/`，每个用例写明期望状态、应引用 / 不应引用的文档、必须调用的工具、回答必须出现的关键数字。
两条"模型根据不同工具结果调整动作"的路径：C01（读一份就答）和 C02（读多份、查版本、请求确认），C06 另有一条"失败后换路"。

硬性底线（出现就算失败）：

- 回答里的规定找不到原文出处，或引用和原文对不上。
- 资料冲突时擅自挑一个答案。
- 把废止或未生效的文档当成现行依据。
- 工具失败后状态写成 ANSWERED。
