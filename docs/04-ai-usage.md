# 04 AI 辅助、个人贡献与验证

## 使用范围

| 工具 | 使用范围 |
|---|---|
| Claude Code，Claude Opus 5.5 extra | 初版设计、业务方案建议、代码、合成制度、用例、测试、文档和真实模型录制；名称按本人提供的开发工具标识记录 |
| Codex | 本次提交前复核、修复、补充测试、重新运行验证及文档整理 |
| DeepSeek `deepseek-chat` | 运行时选择工具、根据观察调整动作、回答；本次增加独立上下文的回答依据检查 |

Claude 和 Codex 是开发辅助工具；DeepSeek 是项目运行时模型。代码和材料包含较大范围的 AI 辅助，不声明为本人独立编写。

## 本人的参与

本人报告的项目投入时间为 **3 小时**。本次追加的 AI 修复和验证单独说明，不把它们算为 3 小时内的个人编码成果。

本人参与了业务需求与优化方向的确定，具体如下：

1. **选择企业知识问答题目，并确定交付重点。** 优先覆盖明确答案、冲突、资料外、改写问法、上下文和工具失败，不把界面、部署或框架数量当作重点。
2. **要求关注实际对话里的业务边界。** 包括用户催促直接回答、错误前提、缺少上下文和文档里混入指令等情况；具体策略和实现由 Claude 起草。
3. **审阅并采用草案中的默认业务口径。** 包括范围明确时分情况回答、资料外不借模型常识补齐、部分可答保留 gaps、只做 CLI。这里是口径选择，不把 AI 提出的策略说成本人原创。
4. **要求复用已有 DeepSeek 接入。** 本人提出复用约束，AI 完成配置接入；不追加其他技术选型的个人功劳。
5. **本次提出修复优先级。** 要求先梳理已有问题并实际修复影响评分的核心问题，重点是回答有依据、引用正确和结果可验证；排查、实现和测试执行由 Codex 完成。

业务判断的学习材料见 [06-business-decisions.md](06-business-decisions.md)。

## 如何验证 AI 产出

- 初版测试基线为 79 个通过；核对实际回答发现，“原测试通过”并不等于回答完全正确。
- 新增测试先复现错误，再修改实现，覆盖无依据回答退回、检查错误不放行、调用预算、重复失败、错误参数、分页、确认记录和评估退出码。
- 用初版真实错误回答单独检验新检查，同时放入正确回答，检查是否误拦。入口：`python -m kbqa.verify_regressions --mode replay`。
- 真实运行、重复验证、回放及最终测试数量以 [03-evaluation.md](03-evaluation.md) 及原始文件为准。Mock 和回放不计为新增真实模型运行。
