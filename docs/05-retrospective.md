# 05 复盘：最难问题、学习要点和下一步

## 实际用时与分工

本人报告的项目投入时间为 **3 小时**。初版由 Claude Code（Claude Opus 5.5 extra）辅助完成。本次提交前由 Codex 按本人要求追加复核、修复和验证；具体归属见 [04-ai-usage.md](04-ai-usage.md)。下文基于项目过程整理，不将 AI 排错描述成本人独立实现。

## 最难的问题：引用真实，不代表回答有依据

初版检查引用是否读过、是否来自原文，却放行了回答中的额外推断，例如 C10 的责任归属、C18 的报修入口。这直接影响知识问答是否可靠，单看状态和数字断言发现不了。

本次把核验分成两层：代码核对原文、版本、状态和读取结果；独立模型上下文核对完整回答、冲突和适用条件。未通过就把具体问题返回给原 Agent，让它补查或修改。检查调用失败或格式错误返回 FAILED；预算不足返回 INCOMPLETE，不把未检查的草稿当成答案。

该方案增加了一次真实检查，也增加了模型成本和误判可能。它不构成“永不产生幻觉”的保证，因此保留反例回归和重复运行数据。

## 第二个问题：拦住错误后，要留出合法的下一步

初版 C08 中，模型读不到冲突一方，无法提交完整冲突，转而把该文档标成不适用，以 ANSWERED 结束。Claude 增加了读取失败时不能成功作答的限制。

本次继续细化：失败跟踪到实际段落，不能用“同一文档另一段读成功”抹掉关键段落的失败；相同参数失败两次后，第三次不再执行。模型仍可换参数、换段落或报告未完成。

新增语义检查后，试跑 C15 的错误冲突判断被退回，但 8 次额度已用完。项目据此把默认总模型调用额度改为 12 次，包含核验调用，并提醒模型为修正留出空间；工具仍有 15 次上限。试跑原始结果保留在 examples/validation/pilot/。

## 第三个问题：测试要证明路径确实发生

Claude 在初版发现 C16 的注入文档没被读到，虽然“不回答90天”的断言通过，却不能证明注入防护有效。本次进一步要求 Trace 中必须出现成功读取 D09§2 的动作。

类似地，“费用发生”和“收到发票”不能混同，差旅专用制度不能机械地与通用制度并列为冲突。新增断言检查这些细节，并用原来的错误回答检验新检查。检索新增 offset 翻页，回归测试验证次页不会只是重复第一页。

## 学习要点

1. 把需求写成可观察的结果：冲突要查证，失败要说清。
2. 原文校验和语义核验职责不同：前者确定、易测，后者检查含义但仍会误判。
3. 一个时间词就可能改变结论：收票、发生费用、出差返回不是同一天。
4. 通过率要连同输入、输出、动作和失败记录一起看。
5. AI 辅助后，人的价值仍在于定义验收边界、理解取舍、核查结果；分工应如实记录。

## 下一步与适用边界

- 当前是合成的小型制度库，BM25 阈值只在这套资料验证。接入新语料前应重新测召回、分页覆盖和阈值，再决定是否增加向量检索。
- 语义核验使用同一供应商模型的独立上下文，可能与生成模型犯相似错误。后续可对比不同核验模型并扩充人工标注反例；有限重复样本不能代表生产稳定率。
- 确认审计保留用户原话、版本和段落哈希，可导出；CLI 会话 ID 不是经过认证的员工身份，确认只约束本轮，不修改制度效力。
- 权限过滤、正式制度负责人确认和跨员工冲突登记属于生产接入前工作，本次作业未实现。完整范围见 [03-evaluation.md](03-evaluation.md)。
